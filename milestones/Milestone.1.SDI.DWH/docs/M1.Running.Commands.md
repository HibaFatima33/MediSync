# Milestone 1 running commands

Use Windows PowerShell from the project root and keep PostgreSQL running. Use the current Windows gateway address instead of the example 172.17.128.1 if different.

## Windows API terminal

```powershell
.\.venv\Scripts\python.exe .\milestones\Milestone.1.SDI.DWH\code\start_query_layer_api.py --host 172.17.128.1 --port 8765
```

Keep this terminal running. Do not start the M2 API on the same port at the same time.

## Copy M1 DAG from another Windows terminal

```powershell
wsl -d Ubuntu --exec mkdir -p /home/p/airflow/dags
wsl -d Ubuntu --exec cp "/mnt/d/IDA'26/Project Phase 1/milestones/Milestone.1.SDI.DWH/airflow_dags/sdi_query_layer_dag.py" /home/p/airflow/dags/pharma_phase1.py
```

## Ubuntu Airflow terminal

```bash
source /home/p/pharma-airflow/.venv/bin/activate
export AIRFLOW_HOME=/home/p/airflow
export PHARMA_API_URL=http://172.17.128.1:8765
curl --max-time 10 "$PHARMA_API_URL/health"
airflow standalone
```

Open localhost:8080, sign in and trigger pharma_phase1. Wait for all three tasks to succeed. If Airflow already runs, restart that instance rather than starting a second one.

## Optional Ubuntu watcher terminal

After activating the same Ubuntu environment:

```bash
python "/mnt/d/IDA'26/Project Phase 1/milestones/Milestone.1.SDI.DWH/code/watch_csv_and_trigger_airflow.py" --config "/mnt/d/IDA'26/Project Phase 1/milestones/Milestone.1.SDI.DWH/config/config.json" --dag pharma_phase1
```

The watcher waits for stable changed contents. Add --initial-load only if you want a startup request. Use --dag sales_demand_visuals explicitly to watch with the extended workflow instead. Leave its generation option off for watcher-triggered runs.
